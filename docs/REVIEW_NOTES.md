# TutorLink - Review Notes & System Status Report (`REVIEW_NOTES.md`)

## Executive Summary
TutorLink has been polished against the project Functional Design Document (FDD). The application runs seamlessly on XAMPP (Apache + MySQL / MariaDB) with zero-config SQLite fallback resilience.

---

## FDD Alignment & Summary of Changes

### Part A - Tutor Document Verification & Approval Removal
- Removed `diploma_status`, `tor_status`, `id_status`, and `approval_status` from `database.sql`, `api/config.php`, `api/register.php`, `api/tutors.php`, `api/match.php`, `api/matches.php`, `api/sessions.php`, `api/admin.php`, `admin.php`, `app.js`, and `index.php`.
- Tutors become visible and bookable immediately upon registration as long as `deactivated = 0`.
- Created `migration.sql` for existing MySQL databases.

### Part B - API Bug Fixes
- **MySQL Login Fix:** Created `failed_login_attempts` in `database.sql` and `migration.sql` using MySQL `INT AUTO_INCREMENT PRIMARY KEY` and removed inline SQLite `CREATE TABLE` from `api/login.php` and `admin-login.php`.
- **Notification User IDs:** Updated `notify()` calls in `api/payment_provider.php` and `api/sessions.php` to pass User IDs (`$student['id']`, `$tutorRecord['id']`, `$session['student_id']`, `$session['tutor_id']`, `'ADMIN-001'`) so alerts correctly reach target user accounts.
- **Schema Alignment:** Synchronized `database.sql` and `api/config.php` definitions (`payments.ref_no` UNIQUE, `idx_notifications_role_target` index).
- **Error Privacy:** Masked detailed SQL migration errors in `api/config.php` and `api/register.php` with safe user response messages.

### Part C - Landing Page Non-Clickable Info Boxes
- Removed button role, tabindex, `.feature-card-interactive` class, and click/keydown event handlers from feature cards and audience cards in `index.php` and `app.js`.
- Removed hover lift/gold border from `.feature-card` in `styles.css`.
- Added "Admin Login" link in `index.php` footer.

### Part D - Student Auto-Validation
- Set student default `validated = 1` on registration in `api/register.php`.
- Removed student validation check from `api/sessions.php`.

### Part E - Admin Portal FDD Strict Implementation & Design Decisions
- **Strict FDD 14 Functions & Naming Rules:**
  - Removed the word "Manage" from all sidebar items and headers (`Dashboard`, `Students`, `Tutor Matching`, `Schedule`, `Payments`, `Notifications`, `Reports`).
  - Section titles, tabs, and action buttons use exact FDD names: `View Student List`, `Validate Student List`, `Review Matching Results`, `Approve Matching Sessions`, `Cancel Matching Sessions`, `New Calendar Schedule`, `Modify Sessions Schedule`, `New Payment Records`, `Confirm Payment Status`, `Send Notifications`, `View Notifications`, `View Completed Tutoring`, `View Weekly Sessions`, `View Monthly Sessions`.
- **Approve Matching Sessions vs. Automatic Payment Confirmation:**
  - Matches generated by students start as `Pending Review`. Admin approval updates `matches.status` to `Approved` and notifies both student and tutor.
  - Session bookings paid via GCash remain automatically confirmed upon successful payment (`sessions.status = 'Confirmed'`). Match review status and session booking confirmation status remain strictly decoupled.
- **Complete Removal of CSV Export:**
  - Deleted CSV download buttons and `format=csv` processing from `api/reports.php` and `admin.php`.
  - Removed `sanitizeCsvCell` helper. Requesting CSV returns a clear `422 Unprocessable Entity` response instructing users to use `Print Report`.
- **Audit Logging:**
  - Added `admin_audit_log` table (schema migration version 4) and `logAdminAction()` helper in `api/helpers.php`.
  - Every administrative state change logs admin ID, action name, target ID, old value, and new value, displayed in the "Recent Admin Activity" list on the Dashboard.
- **Status Transition Rules (Forward-Only):**
  - Confirmed sessions can transition to `In Progress`, `Completed`, or `Cancelled`.
  - In Progress sessions can transition to `Completed` or `Cancelled`.
  - Completed and Cancelled statuses are final and cannot be reverted.
  - Reverting payment status from Confirmed to Pending is blocked if the linked session is `In Progress` or `Completed`, or if payout has been processed.
